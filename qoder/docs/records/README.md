## 能否用「导出的对话文本」替代截图？

**可以放，但不能替代。**

赛题原文指定的是「截图**或**录屏」二选一，评审按材料清单核对时会找这两样之一。
纯文本文件无法自证来源——任何人都能写一段 Markdown 冒充 Qoder 对话，
因此它的证据强度低于带界面痕迹的截图，不能单独作为第 5 项材料提交。

**但强烈建议作为补充材料一并归档**，好处是评审点开仓库即可翻阅完整对话脉络：

- 若 Qoder 支持导出本次会话（Markdown / JSON），把文件放本目录即可；
- 若 Qoder 支持生成会话分享链接，把链接写进提交材料，它的说服力比截图更强
  （因为链接直接指向 Qoder 平台上的真实记录）；
- 命名建议 `00-完整对话记录.md` 或 `.json`。

一句话：**第 5 项本身必须是截图或录屏；文本/链接是加分项，不是替代项。**

## 截图要点

- **只截你发的提示词没有用**，必须同时能看到 Qoder 的回应或它执行的文件操作，
  否则证明不了代码是它产出的。
- 一屏能放下就别拆成两张：优先截「你的输入 + 它的产出」在同一窗口内的连续对话。
- 不必每个阶段都截。上表 6 张覆盖了"需求 → 写代码 → 改 bug → 验证 → 成果 → 归属"完整链路。

## 与验收产物的区别

`docs/screenshots/` 下的是**成品界面截图**，由本机渲染生成，与代码状态同一次提交，
用于说明「跑起来是什么样」；`docs/records/` 下的是**过程截图**，用于说明
「是怎么在 Qoder 里做出来的」。两者不能互相替代。

各轮提示词原文保存在仓库根目录（`01-提示词-*.txt` ~ `12-提示词-*.txt`），
可以与截图对照，见 README「开发过程留痕」一节。
