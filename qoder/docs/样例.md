### seekdb 发挥作用的记录

页面 SQL 面板展示的就是**真实执行的那一条**（`build_sql()` 生成，`search()` 内部调用同一个函数）：

```sql
SELECT c.id, c.heading, c.line_start, c.line_end, c.content, n.file_path,
       c.dir_type, c.year, c.tags, MATCH(c.content) AGAINST('重排') AS score
FROM note_chunks c JOIN notes n ON n.id = c.note_id
WHERE MATCH(c.content) AGAINST('重排')
  AND c.dir_type = '11-赛题归档'
ORDER BY score DESC LIMIT 3
```

这三点可以核验 seekdb 确实在链路上，而不是"查了个 JSON 假装是数据库"：

1. **`MATCH ... AGAINST` 是 seekdb 的全文索引检索**，`score` 由 `MATCH` 表达式直接产出，不是应用层算的；
2. **过滤条件 `c.dir_type` 在 SQL 层完成**（`note_chunks` 上带 `idx_dir_type`），不是取回后在 Python 里筛；
3. **`line_start`/`line_end` 是从库里读出来的字段**，直接从 `note_chunks` 返回给前端。

## 3. 样例二：ngram 的必要性对照（技术发挥作用的记录）

这一组是**唯一变量对照**：同一份数据、同一关键词，唯一差别是全文索引的分词器。

**输入**：关键词 `重排`

**操作步骤**：

```bash
python tools/ngram_compare.py
```

脚本做的事：先用现库（ngram 索引）查命中数，再建一张同内容、同结构但**全文索引不带 ngram**
的临时表，跑同一条 `MATCH` 查询。

**预期结果**（实际输出）：

```
关键词 '重排'
  ngram 索引命中 : 19
  默认分词器命中 : 0
--- 其余关键词（ngram）---
  混合检索 -> 38
  缓存 -> 21
  ngram -> 142
  策略 -> 9
```

**结论**：默认分词器把整段中文当一个 token，`重排` 匹配不到 `检索重排`，命中 **0**；
换成 ngram 分词器后命中 **19**。这就是"为什么必须 `WITH PARSER ngram`"的直接证据。

同一条结论由自动化测试守着，不必手工跑脚本：

```bash
python -m pytest backend/tests/test_search.py -k ngram -v
```


## 4. 样例三：出处行号的严格校验

这个样例用来证明「行号 99-116」不是随手写的，而是被机器逐个核对过的。

**操作步骤**：

```bash
python tools/verify_chunks.py --all
```

**预期结果**（实际输出）：

```
验证结果: 219 OK / 0 BAD
```

全库 219 个块，逐个把「数据库里的 content」与「原文件该行区间的实际内容」**逐字比对**，
并检查三件事：起始行必须是 `## ` 开头且与 `heading` 一致、`line_end` 不得越界、
去掉尾部空行后必须完全相等。

**反向验证（证明这个检查不是走过场）**：

```python
原始数据           : True
行号整体 +1        : False  ['内容不匹配（严格比对）']
line_end 多算 5 行 : False  ['内容不匹配（严格比对）']
heading 改错       : False  ["起始行非 H2: '# 2026 OceanBase 数据库大赛 · 总索引'"]
```

行号偏 1 行、多算几行、标题串了——三种都会被判 BAD。
（上一版检查是"内容互相包含即算通过"，这三种情况**全部会误判为 OK**，现已改为严格相等。）

## 5. 样例四：特殊字符与注入

**输入**：带双引号的关键词 `policy"id`

**操作步骤**：浏览器打开

```
http://127.0.0.1:8000/?q=policy%22id&top_k=2
```

**预期结果**：

- 搜索框原样显示 `policy"id`；
- 卡片可以正常点击展开（高亮用的关键词与输入**完全一致**，没有被双引号截断）；
- 开发者工具里 `document.querySelector('.result-card').dataset.keyword` 返回 `policy"id`；
- 页面结构完整，没有多出任何事件属性。

再输入 `" onmouseover="alert(1)`：不弹窗，卡片正常渲染，该载荷被完整关在属性值内部。
截图见 `docs/screenshots/web-quote.png`。

这一条对应的是"关键词会拼进 DOM"这个真实风险：属性值必须用 `escapeAttr`
（额外转义 `"` 和 `'`），文本节点用 `escapeHtml`，两者不能混用。

## 6. 一键复现清单

```bash
# 0) 环境
pip install -r requirements.txt          # Python 3.13.5 / pylibseekdb 1.4.0.post2

# 1) 建索引（初始数据）
python -m backend.app.cli index --rebuild     # 期望：库内合计 26 篇 / 219 块

# 2) 样例一
python -m backend.app.cli search "重排" --type exam --top-k 3   # 期望：首条 行 99-116，score 2.9853
python -m backend.app.cli show 2000012                          # 期望：行 99-116 原文

# 3) 样例二
python tools/ngram_compare.py                                  # 期望：ngram 19 / 默认 0
python -m pytest backend/tests -q                              # 期望：23 passed

# 4) 样例三
python tools/verify_chunks.py --all                            # 期望：219 OK / 0 BAD

# 5) 样例四 / Web
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
#   打开 http://127.0.0.1:8000/?q=重排&type=exam&top_k=3
```

> **注意**：seekdb 是嵌入式单进程数据库，同一个库目录同时只能被一个进程打开。
> 跑 CLI 或 pytest 前请先停掉 Web 服务，否则会卡在打开数据库这一步。
