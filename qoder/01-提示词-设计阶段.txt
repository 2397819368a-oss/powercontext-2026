我要做一个 Obsidian 笔记库的「带出处检索助手」，解决我自己的真实痛点：

我在 Obsidian 里维护一个学习笔记库，路径 D:/新建文件夹/Obsidian/吉米，
结构是 10-MOC与索引 / 11-赛题归档 / 12-原子卡片 / 13-代码片段 / 14-文献卡片
五个目录，共 29 个 Markdown，223 个二级标题，多数文件有 YAML frontmatter
（含 title / date / tags / status 字段，tags 采用 类型/xxx、赛题/xxx 这样的斜杠命名空间）。

痛点是：我记得"以前写过一段关于 X 的东西"，但 Obsidian 自带搜索是纯关键词匹配，
换个说法、用词不同就搜不到，等于白存。比如我记得有过"重新排序"的内容，
但笔记里通篇写的是"重排"，直接搜"重新排序"什么都搜不出来。

请帮我做一个本地运行的 Web 应用，核心能力是：输入一句自然语言描述，
返回最相关的笔记片段，每条结果必须带 文件路径 + 所属小节标题 + 行号范围 作为出处，
让我能一键跳回原文。同时要能按「目录类型 / 标签 / 年份」做结构化过滤。

技术约束：
- Python 3.11+，数据层用 seekdb（嵌入式，pip 包名 pylibseekdb），不要用 sqlite/mysql 替代
- 中文检索必须用 ngram 分词（FULLTEXT KEY(...) WITH PARSER ngram），
  用默认分词器对中文会返回 0 命中
- 必须同时支持「关键词检索」和「结构化过滤」，且两者能叠加
- 不引入需要联网的外部服务；embedding / LLM 做成可选开关，默认关闭也能完整跑通

先不要写代码。请先输出一份设计方案，包含四部分：
1. 目录结构与模块划分
2. 数据表设计（字段与索引，说明为什么需要 ngram）
3. ingest 流程：怎么按 H2 切块、怎么记行号、怎么解析 frontmatter 的 tags 和 date
4. 检索流程：关键词和结构化过滤怎么叠加，打算怎么验证"结果确实相关"

等我确认后再进入实现。
