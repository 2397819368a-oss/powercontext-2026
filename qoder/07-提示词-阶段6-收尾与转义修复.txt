【不成立的一条：你说的「双引号也不会破坏 JS」】
(d) 你验证的是 /api/search 这个接口，接口通了不等于页面点击能用。
当前的写法是：data-keyword="${escapeHtml(q)}"
escapeHtml 走的是 div.textContent → innerHTML，只转义 & < >，不转义双引号。
把它放进双引号属性里就会截断。我用 HTML 解析器实测：
  关键词 policy'id              → data-keyword = "policy'id"   一致（单引号是运气好）
  关键词 policy"id              → 生成 data-keyword="policy"id"  → 浏览器取到 "policy"
  关键词 " onmouseover="alert(1) → 属性直接断开，注入出一个真的 onmouseover 事件
也就是说：带双引号的关键词，点击卡片后用来高亮的关键词是错的；再往前一步就是 XSS。
这个页面的卖点之一就是"带特殊字符不乱"，这条必须修掉，不能留。

【必修 1：属性值转义】
在 index.html 里新增一个专门给属性用的转义函数（不要改 escapeHtml 的语义，它还要用于文本）：

  function escapeAttr(text) {
    return escapeHtml(text).replace(/"/g, '&quot;').replace(/'/g, '&#39;');
  }

然后把所有"插到 attr=\"...\" 里"的位置换成 escapeAttr：
  - data-keyword="${escapeAttr(q)}"
  - title="${escapeAttr(r.file_path)}"
文本节点（小节标题、摘要、文件名显示、标签）继续用 escapeHtml，不要混。
判断标准很简单：这个值是不是落在引号里面。是 → escapeAttr。

  while seg and seg[-1].strip() == "":
      seg.pop()
  expected = "\n".join(seg).strip()

      报 BAD，并打印首个差异位置前后 20 字
