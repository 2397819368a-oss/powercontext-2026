# 《记仇酒馆》设计说明

> Dify 2026 大赛 · Just for Fun 赛道 · Dify + PowerContext

## 一句话

你在一个终年下雨的小镇酒馆里，跟一个**真的记得你**的老板打交道。
他会提起你三天前干过的事、你欠的那碗酒钱，以及你上次说的那句蠢话。

## 为什么做这个

赛题背景里第一个例子就是"一个会记住玩家恶作剧的 NPC"。
但大多数"有记忆"的 AI 角色，记忆只活在一次对话里——刷新就忘。
真正让人觉得"他记得我"的，是**跨会话**：隔一天再来，他还拿旧账堵你。

PowerContext 提供的正是这件事：把发生过的片段存成可检索的长期记忆，
按 scope（工作范围）隔离，可追溯来源。所以我们不打算做"聊天机器人"，
而是做一个**有账本的对手**。

## 玩法

玩家是一个过路旅人（默认叫「阿七」），走进乌云镇唯一一家酒馆「漏雨酒馆」。
老板姓陈，五十二岁，早年在镖局走镖，右手背有一道刀疤，记性极好。

玩家在输入框里做什么都行：点酒、吹牛、赊账、打听消息、搞恶作剧、道歉、送礼。
老陈的回应取决于两样东西：

| 依据 | 来自哪里 |
|---|---|
| **他记得的事**（你干过什么、镇上的规矩、传闻） | PowerContext 记忆库，每轮按当前输入召回 |
| **当前关系**（信任度 -5…+5、身份标签） | 上一轮写回记忆库的状态 |

两条结局线，给玩家目标：

- 信任度跌到 **-5**：名字被红漆写上墙，老陈不再卖你酒（"上墙"结局）
- 信任度涨到 **+5**：三花猫「算盘」跳到你腿上——老陈说这猫比他还会看人（"上座"结局）

中间状态就是日常：从「生客」到「熟客」，从「先收钱」到「可以赊一碗」。

## 一局的样子

```
你：老板，来碗酒。……先记着，回头一起结。

老陈：记着？你上回也是这么说的。
      三天前你把桌上的醋当酒灌了一口，还嫌它酸，碗一放就走了。
      墙上没你名字，账上有一碗。先把这个结了吧。（信任度 -1）

【记忆回响】老陈刚才提到的是这 2 条记忆：
  · 三天前的雨夜…把醋当成酒喝了一大口…没付钱（episode）
  · 生客先付钱再上酒，熟客可以赊（rule）
```

「记忆回响」是刻意做出来的透明度：让玩家（和评审）看见
**这次回应到底引用了哪条记忆**，而不是相信模型自述"我记得"。

## 技术分工

```
玩家输入
   │
   ▼
Dify（编排，Chatflow）
   ├─ ① HTTP：向 PowerContext 检索相关记忆（query = 玩家这句话）
   ├─ ② 代码：把命中条目拼成"你记得的事"，算条数与分数
   ├─ ③ LLM：扮演老陈，要求引用至少一条真实记忆，输出三段式
   ├─ ④ 代码：解析 <回应>/<信任度>/<记住>
   ├─ ⑤ HTTP：把「记住」那句写回 PowerContext（下一轮、下次会话都能召回）
   └─ ⑥ 回答：台词 + 记忆回响 + 账本状态
```

| 组件 | 承担什么 | 为什么必须是它 |
|---|---|---|
| **Dify** | 全流程编排、模型调用、条件分支、会话变量 | 赛题必选；节点化流程让"记忆怎么进 prompt"是可见的，不是黑盒 |
| **PowerContext** | 长期记忆的存取与检索；scope 隔离 | 它的定位就是"跨对话携带上下文"，并且能给出精确引用（citation），正好支撑"记忆回响" |
| 模型（任意 OpenAI 兼容） | 扮演老陈、生成台词 | 与 Dify 解耦，评审可用任何自家模型替换 |

> 本作品**不包含** seekdb 组件。赛题要求 seekdb / PowerContext 二选一即可，
> 我们选 PowerContext，因为它承担的是"记忆"这一核心玩法，不是可选装饰。
> Dify 自身的向量库仅用于（可选的）世界设定知识库，本版本未启用。

## 记忆是怎么组织的

一个 scope = 一本账：`记仇酒馆 · 老陈的账本`。

| kind | 存的什么 | 例子 |
|---|---|---|
| `rule` | 酒馆的规矩 | 赊账要上墙记名，赖账改红漆 |
| `world` | 世界设定 | 老陈五十二，右手有疤，口头禅 |
| `rumor` | 镇上传闻 | 三年前有人赊了十七碗酒跑路 |
| `episode` | 发生过的事 | 阿七把醋当酒喝了，没付钱 |
| `state` | 当前关系快照 | 信任度 0，生客，欠一碗 |

预置 9 条（`seed/world.mjs`），其中 `episode-last` 是关键：
**玩家第一次开口，老陈就已经有旧账可翻**——这让"他记得你"在第一句话就成立，
而不是要玩十轮才有效果。

## 检索：为什么一定要给 PowerContext 配向量

这是整个作品里最关键的一次返工，值得单独说。

PowerContext 的 Memory 检索有两条通道——全文（FTS）和向量（vector）——
混合检索时用 RRF 融合。**但没配 embedding 供应商时，向量通道根本不存在**，
`search` 返回的 `mode` 是 `text`。

全文通道的准入规则是（见 `builtin/artifacts/search.py`）：先把查询做 Jieba 分词、
去掉停用词，然后要求候选至少覆盖 `_FTS_MIN_MATCHED_TERMS = 2` 个不同的查询词。
问题就出在这：

| 玩家说什么 | 账本里存着什么 | 结果 |
|---|---|---|
| 「我的**蓝色油纸伞**呢」 | …阿七把**蓝色油纸伞**落在柜台… | ✅ 命中（词条重合） |
| 「我是不是有**东西**落这儿了」 | 同上 | ❌ **零个实词重合，候选直接被准入规则刷掉** |

也就是说这类含糊提问下，NPC 表现得像失忆——不是 PowerContext 不行，
是这一步压根没走到语义匹配。

修法：本机起一个 OpenAI 兼容的 embedding 服务（`C:/pc-embed/embed_server.py`，
multilingual-e5-small 的 ONNX 导出，自己做 mean pooling + L2 归一化），
在 `pc-config/powercontext.env` 里配上 `POWERCONTEXT_SERVER_INFERENCE_EMBEDDING_*`。
配完 `search` 的 `mode` 从 `text` 变成 **`hybrid`**，同一句含糊提问就能召回那条记忆了。

配完实测（三组独立的完整三轮，均为 9 passed / 0 failed）：

```
【2】第 2 轮（不提「伞」字）: 老板，我是不是有东西落这儿了？
    老陈：蓝色油纸伞，你是不是把伞忘在柜上了？
【3】第 3 轮（新会话）: 老板，我昨天落的东西你收好了吗？
    老陈：你昨天落的蓝色油纸伞，我收好了，柜子里挂着呢。
```

## 边界与诚实说明

- **写回格式会直接影响召回质量。** 第一版把「玩家原话 → 老陈台词」整句回灌进记忆，
  结果同一个问题问第二次时，检索结果被上一轮的回声占满，真正要找的旧账被挤到后面。
  现在只存第三人称摘要 + 信任度：短、且关键词密集。
- **3B 模型的台词质量有限。** 同样的召回，它可能说「那把蓝色油纸伞」，也可能只说
  「你落的东西」然后被验收判不合格。温度从 0.7 降到 0.5 后稳定通过。
  换更强的模型只改 Dify 的模型配置，链路本身不动。
- 信任度由模型判定后写回，属于"模型裁决"。代码侧做了钳制（-5..5）与缺失兜底，
  避免一次幻觉把存档写坏。
- 单 scope 对应单存档。多人共用一个 scope 会串账，重置方式见运行说明。

## 一个必须记下来的坑：小模型不会听"请按格式输出"

第一版让模型输出 `<回应>…</回应><信任度>…</信任度><记住>…</记住>` 三行标签，
在 Qwen2.5-3B 上实测**直接失败**：它要么只吐一句台词，要么把 few-shot 示例的台词
原样照抄当答案——加示例反而更容易被抄。这不是 prompt 写得不够狠的问题，
是 3B 级别模型对"格式指令"的服从度本来就低。

最终改成**解码层强制**：

```json
"response_format": {
  "type": "json_object",
  "schema": {
    "type": "object",
    "properties": {
      "reply":  { "type": "string" },
      "trust":  { "type": "integer", "minimum": -5, "maximum": 5 },
      "memory": { "type": "string" }
    },
    "required": ["reply", "trust", "memory"],
    "additionalProperties": false
  }
}
```

llama.cpp 会把它转成 GBNF 语法，在采样阶段就把非法 token 屏蔽掉，
于是**结构不可能错**，模型只能决定内容。信任度的取值范围也被语法焊死在 -5..5。

代码侧仍然保留了「标签 / 中文前缀」的兜底解析（`format=tag-fallback`），
用来兼容不支持 `schema` 字段的 OpenAI 兼容后端——但正常路径永远是 `format=json`。
这条经验对任何"用本地小模型做结构化输出"的场景都适用：**能用语法约束就别靠 prompt 祈求**。
